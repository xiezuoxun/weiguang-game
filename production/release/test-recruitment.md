# 《微光归处》测试招募计划（限量内测）

> 目标：在发布前验证 **真机帧率 / 触控手感 / 文案共情**，并完成 Phase 7 留存的「真机降级帧率补录项」。
> 周期：**2 周**（招募 → 试玩 → 回收 → 汇总）。
> 负责人：路远行（发行 / 社区）。

---

## 1. 招募定位与渠道
我们找愿意慢下来、被旧物故事打动的人。优先覆盖 **低端安卓机、老 iPhone、核显 / 老 Mac 桌面端**——这些是真机帧率与触控验收的关键样本。

| 渠道 | 形式 | 备注 |
|------|------|------|
| **TapTap 票圈 / 动态 + 官方话题** | 招募帖（见 §5 模板）+ 设备档位问卷 | 主阵地，便于精准触达手游用户 |
| **微信群 / QQ 群** | 群公告 + 问卷接龙 | 老玩家与核心叙事向用户沉淀 |
| **本地（线下）** | 高校社团 / 独立游戏咖啡馆 / 同城桌游局海报 + 扫码 | 覆盖非线上活跃但具共情力的样本 |
| 备选 | Steam 社区 / WeGame 圈（桌面端样本补充） | 视桌面构建进度启用 |

## 3. 入选标准与配额（覆盖低端机与桌面）
- **配额矩阵**（总样本建议 60–100 人）：

| 档位 | 设备示例 | 目标样本 | 验收重点 |
|------|----------|----------|----------|
| 低端安卓 | 红米 Note 12 / RAM≤4GB / Android 13 | 20–30 | 真机帧率 ≥30fps、触控手感 |
| 中端安卓 | 主流机型 / RAM 6–8GB | 15–20 | 画质 / 帧率平衡 |
| 老 iPhone | iPhone 11 / 13 / iOS 16–17 | 15–20 | 触控、发热 |
| 桌面（核显/老 Mac） | 核显本 / Apple M1 / 老 Intel Mac | 10–15 | 桌面映射、帧率 |

- **入选优先级**：设备档位能补齐矩阵空白者优先；叙事共情自述 + 稳定反馈意愿次之；同一机型不重复超额。
- **排除**：无法提供机型/RAM 信息者、曾恶意刷评者。

## 7. 与真机帧率验收的衔接（关键）
- **验收口径**（对齐 `production/phase7-closure-decision.md` 留存项）：低内存机（≤1024MB）**Profiler / FPS 计数器实测 ≥30fps**；桌面 / 高内存机保持更高画质。
- **数据回流**：试玩包内置 FPS 浮窗，反馈模板 §4-2 强制录均值与掉帧场景；汇总后形成「机型 × 帧率」矩阵，作为 Phase 7「真机降级帧率补录项」的验收证据。
- **降级策略验证**：确认 `DustBudget` 封顶（≤64 格）与 `DustReveal.shader` `_GridRes` 降采样（8×8→6×6）在低端机生效；若仍 <30fps，回流工程侧调参（不阻塞文案/商店页推进）。
- **闭环**：内测报告结论回写 `phase8-release-checklist.md` 的「真机帧率 ≥30fps」项，达标即由 🟡 转 ✅。
